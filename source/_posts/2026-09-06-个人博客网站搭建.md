## 前言

这是我的个人博客的第一篇正式文章，用来记录整个站点的搭建过程。

这个博客基于 **Hexo** + **Stellar** 主题，托管在 **GitHub Pages** 上。文章不会讲 Hexo 的基础命令（官方文档写得很清楚），而是把整个搭建过程中**真正做过的关键决策、踩过的坑、调试思路**讲清楚，方便以后自己回顾，也希望对想用同样技术栈的朋友有点参考价值。

## 一、技术选型

### 为什么是静态博客？

> 在说具体框架前，先把"静态博客"这件事讲清楚。

传统博客（WordPress、Typecho 等）是**动态网站**：服务器每次收到请求都要从数据库读文章内容、拼出 HTML 再返回给浏览器。好处是后台写文章很方便，缺点是你得**一直维护一台服务器**（续费、备份、防攻击……）。

**静态博客**反过来：**所有文章在本地一次性生成 HTML 文件**，部署时直接把这堆 HTML 上传到一个静态托管服务就行。访问者打开网页时，服务器直接返回现成的 HTML，连数据库都没有。

| 维度 | 动态博客 | 静态博客 |
|---|---|---|
| 服务器要求 | 需要 Node/PHP + 数据库 | 任何能托管静态文件的服务器 |
| 维护成本 | 高（备份、更新、安全）| 几乎为零 |
| 写文章 | 后台富文本编辑器 | 本地 Markdown 文件 |
| 评论 | 内置 | 第三方（giscus / Disqus / Twikoo）|
| 速度 | 看服务器性能 | 通常极快（CDN 加速）|

对我来说：博客只是记录生活/学习笔记，**不想为这个再单独养一台服务器**。GitHub Pages 免费、稳定、能绑定自定义域名，完美匹配。

### 为什么是 Hexo + Stellar？

国内最常见的几个静态博客方案：

| 框架 | 语言 | 优势 | 劣势 |
|---|---|---|---|
| **Hexo** | Node.js | 生态成熟、中文资料多、主题丰富 | 大量文件时构建略慢 |
| **Hugo** | Go | 构建极快、单二进制 | 主题模板语法门槛高 |
| **Jekyll** | Ruby | GitHub Pages 原生支持 | Ruby 生态在国内小众，主题少 |
| **VuePress** | Vue | 适合技术文档 | 偏文档风，博客感弱 |

我之前用过 Jekyll（Chirpy 主题）一段时间，体验不错但想换个新鲜的。**Hexo 是中文静态博客圈最主流的方案**（信不信你搜"个人博客搭建"前 10 篇里 8 篇是 Hexo），主题生态丰富，社区活跃，出了问题搜得到答案。

主题选 **Stellar** 的原因很简单：UI 漂亮、设计现代、文档详尽，且作者 xaoxuu 一直在维护更新。

## 二、环境准备

### 2.1 Node.js（必须）

Hexo 是基于 Node.js 的，**版本 ≥ 18** 都能用。

我用的是 Node 22（pnpm 兼容性最好）。如果你还没装，去 <https://nodejs.org/> 下载 LTS 版即可。

验证：

```bash
node -v    # 看到 v18.x 或 v22.x 即可
npm -v
```

### 2.2 包管理器：pnpm（推荐）

Hexo 自带用 npm 装依赖，但 **pnpm 更省空间、装得更快**，强烈推荐。

**踩坑提醒**：Node 16+ 自带 `corepack`，所以**不用单独装 pnpm**，直接：

```bash
corepack enable
corepack prepare pnpm@latest --activate
pnpm -v    # 应能输出版本号
```

如果 `pnpm` 命令不存在，需要设置环境变量或用 corepack 直接调用：

```bash
# Windows + Git Bash 下 corepack pnpm 路径
node "C:/Users/user/.workbuddy/binaries/node/versions/22.22.2-2/node_modules/corepack/dist/pnpm.js" <命令>
```

### 2.3 Git

部署要用，<https://git-scm.com/> 下载安装。

## 三、初始化 Hexo 项目

```bash
# 1. 新建项目目录
mkdir myblog && cd myblog

# 2. 初始化 Hexo（hexo-cli 是全局工具，先装）
npm install -g hexo-cli
hexo init .           # 当前目录初始化

# 3. 安装项目依赖
pnpm install

# 4. 启动本地预览（默认 http://localhost:4000）
pnpm hexo server
```

初始化后目录结构大致是：

```
myblog/
├── _config.yml        # 站点配置（标题、副标题、URL 等）
├── _config.stellar.yml  # 主题配置（稍后单独讲）
├── package.json
├── source/            # 文章、页面、图片等原始素材
│   ├── _posts/        # 博客文章（Markdown）
│   └── about/         # 「关于」独立页面
├── themes/            # 主题目录
│   └── stellar/       # Stellar 主题（git submodule 或普通目录）
└── public/            # hexo generate 生成的最终静态文件（待部署）
```

## 四、安装 Stellar 主题

```bash
git clone https://github.com/xaoxuu/hexo-theme-stellar.git themes/stellar
```

然后在站点根目录的 `_config.yml` 里指定主题：

```yaml
theme: stellar
```

> **重点踩坑**：早期教程会让你用 `git submodule add` 装主题——**强烈不推荐**。
> 
> **原因**：git submodule 会让父仓库只记录"主题指向哪个 commit"，CI 系统拉子模块会去上游仓库找那个 commit。你本地对主题的修改（哪怕只是个小 bug 修复）commit 后，**这个 commit 只存在于你的本地仓库**，GitHub Actions 拉不到，部署必然失败。
> 
> **正确做法**：把主题当作普通目录，git add 直接纳入版本管理。个人博客主题本来就不大（几十 MB），换来的是"主题修改随便 commit，永远不会丢"。

## 五、配置 Stellar 主题

### 5.1 复制示例配置

```bash
cp themes/stellar/_config.yml _config.stellar.yml
```

**关键原则**：把主题的 `_config.yml` 复制到根目录命名为 `_config.stellar.yml` 后，**只改根目录那份**，主题目录里的那份**永远不要改**。这样以后升级主题时不会被覆盖。

### 5.2 必填字段

```yaml
# 站点基础信息
title: L.D.X. 的小屋
subtitle: 记录生活与思考
description: 一个记录学习与生活的个人博客
keywords: Hexo, Stellar, 博客
author: L.D.X.
language: zh-CN

# 头像和图标
avatar: /images/avatar.jpg     # 头像（放在 source/images/）
favicon: /favicon.ico          # 浏览器标签页图标（放在 source/ 根目录）

# URL（注意：GitHub Pages 永远是 https://<用户名>.github.io，**小写**）
url: https://ldx613.github.io
```

### 5.3 侧边栏菜单

```yaml
menubar:
  items:
    - id: post
      theme: '#9BC76A'
      icon: default:documents
      title: 博客
      url: /
    - id: categories
      theme: '#7CB342'
      icon: default:category
      title: 分类
      url: /categories/
    - id: tags
      theme: '#5DADE2'
      icon: default:hashtag
      title: 标签
      url: /tags/
    - id: archives

```

### 5.4 评论（giscus）

giscus 是基于 GitHub Discussions 的免费评论系统，**完全免费、无广告**，只要在仓库开启 Discussions 即可使用。

1. 打开 <https://giscus.app/>，填入你的仓库地址，按提示配置主题、位置等
2. 它会生成一段 `<script>` 标签，里面有 `data-repo-id` 和 `data-category-id`
3. 在仓库 Settings → General → Features → **勾选 Discussions**
4. 主题配置里启用：

```yaml
comments:
  service: giscus
  giscus:
    repo: LDX613/LDX613.github.io
    repo-id: R_kgDOUOGCmg
    category: Announcements
    category-id: DIC_kwDOUOGCms4DE22o
    mapping: pathname
    reactions-enabled: 1
    theme: preferred_color_scheme
    lang: zh-CN
    input-position: bottom
```

### 5.5 RSS 订阅

```bash
pnpm install hexo-generator-feed
```

主题配置里启用：

```yaml
rss:
  icon: default:rss
  text: RSS
  type: rss2
```

部署后访问 `/atom.xml` 即可拿到 RSS。

### 5.6 反盗用检查（必看！）

```yaml
canonical:
  originalHost: ldx613.github.io   # ← 必须是**小写**，否则触发「非法克隆站」提示
  officialHosts:
    - localhost
```

**踩坑实录**：这一项填错会触发 Stellar 自带的反盗用警告，浏览器顶部出现红色提示：

> ☠️ 本站为非法克隆站，请前往官方源站访问。

**根因**：Stellar 客户端 JS 把 `originalHost` 做 base64 编码，跟 `window.location.host` 的 base64 比较，**base64 对大小写敏感**。GitHub Pages 访问域名永远是小写（`ldx613.github.io`），所以这一项必须也是小写，否则永远判定为「克隆站」。

## 六、独立页面

Hexo 默认只有首页和文章页，"分类/标签/归档/关于"这些是独立页面，需要手动建：

```bash
hexo new page categories
hexo new page tags
hexo new page archives
hexo new page about
```

生成的页面在 `source/<页面名>/index.md`，里面需要手动加一段：

```markdown
---
title: 分类
menu_id: categories   # ← 关键：跟 _config.stellar.yml 里 menubar 的 id 对应
---
```

> **踩坑实录**：如果不加 `menu_id`，侧边栏菜单点进去**不会有高亮效果**——你以为是 bug，其实是没告诉主题"当前页面属于哪个菜单项"。

## 七、个性化外观

### 7.1 头像与 favicon

- 头像：`source/images/avatar.jpg`，主题自动识别
- favicon：用任何图片工具生成 `favicon.ico`（推荐尺寸 32×32、48×48），放进 `source/favicon.ico`

> **踩坑实录**：浏览器 favicon 是**缓存最严重的资源**，换 favicon 后必须清浏览器缓存或硬刷新（Ctrl+Shift+R）才能看到新图标。

### 7.2 渐变背景

Stellar 主题用 Stylus 预处理 CSS，主题配置里直接写渐变会被 `convert()` 函数截断（**只取第一个逗号前的内容**）。

**绕坑写法**：把所有渐变放在 `inject.head` 段，用原生 CSS 写：

```yaml
style:
  site:
    background-image: initial   # 占位让主题生成 <div class="sitebg">
  leftbar:
    background-color-light: hsla(95, 45%, 97%, 1)
    background-color-dark: hsla(120, 18%, 16%, 1)
    background-opacity: 0.6
    blur-px: 12px

inject:
  head: |
    <style>
      body > .sitebg {
        background-image: linear-gradient(135deg, #ECF7E1 0%, #D3E8B7 45%, #CDE7FA 75%, #FFF4B6 100%) !important;
      }
      /* 暗色模式对应深色版 */
      :root[data-theme="dark"] body > .sitebg {
        background-image: linear-gradient(135deg, #1a2e1a 0%, #2d4a2d 45%, #1e3a4f 75%, #3d3310 100%) !important;
      }
    </style>
```

**关键点**：

1. `background-image: initial` 是**占位**——如果这个字段为空，主题会**跳过生成 `<div class="sitebg">` 元素**，CSS 再多也无效
2. `!important` 必须加——主题的默认样式优先级很高
3. 同时覆盖亮色 / 暗色两套

## 八、部署到 GitHub Pages

### 8.1 创建仓库

GitHub 上新建一个仓库，命名必须是 `<用户名>.github.io`（比如 `LDX613.github.io`），且**整个仓库名必须用 GitHub 用户名**，跟访问域名一致。

### 8.2 仓库端一次性配置

进入仓库的 Settings：

1. **Pages → Source** 选 **GitHub Actions**（不是 Deploy from a branch）
2. **Actions → General → Workflow permissions** 选 **Read and write permissions**
3. **Environments → github-pages → Deployment branches** 加你的分支（默认只允许 `main`，我们用 `master` 所以要改）

### 8.3 GitHub Actions 部署脚本

在项目根目录新建 `.github/workflows/deploy.yml`：

```yaml
name: 部署到 GitHub Pages

on:
  push:
    branches: [master]

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: 检出代码
        uses: actions/checkout@v4

      - name: 配置 Node
        uses: actions/actions-setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - name: 安装 pnpm
        run: npm install -g pnpm

      - name: 安装依赖
        run: pnpm install

      - name: 构建站点
        run: pnpm hexo generate

      - name: 上传产物
        uses: actions/upload-pages-artifact@v3
        with:
          path: public

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: 部署
        id: deployment
        uses: actions/deploy-pages@v4
```

### 8.4 推送到 GitHub

**踩坑实录**：Windows + Git Bash 在沙箱环境下访问 GitHub HTTPS 时，常报 `CRYPT_E_NO_REVOCATION_CHECK (0x80092012)` 错误，是证书吊销检查失败。

**一次性绕过**：在 push 命令行加 `-c http.sslVerify=false`，不改全局配置：

```bash
git -c http.sslVerify=false push origin master
```

> ⚠️ 只在 push 时临时关 SSL 验证，不影响配置。生产环境请用 SSH key 或 GitHub Actions 的内置 token。

### 8.5 触发部署的细节

GitHub 对 push 有个安全机制：**如果 push 修改了 `.github/workflows/*.yml` 本身，该次 push 不会自动触发 Actions run**（防止有人用恶意 commit 偷 secrets）。

**绕过办法**：
- 先推一个**不含 workflow 改动**的 commit，等部署成功
- 再推**只改 workflow** 的 commit，然后去 Actions 页面手动点 Run workflow

我部署时走了第二个流程：先推 `3412ea9`（含 workflow 改动），GitHub 跳过没跑；然后推 `85fa624`（空 commit "trigger deploy"），自动触发了。

### 8.6 验证

访问 `https://<用户名>.github.io`，看到博客就是成功了。

## 九、写博客的工作流

日常写一篇博客的流程：

```bash
# 1. 创建新文章（hexo 自动加日期前缀）
hexo new "我的新文章"

# 2. 编辑 source/_posts/<日期>-我的新文章.md
#    （frontmatter 里的 categories / tags 会自动生成对应分类页和标签页）

# 3. 本地预览
pnpm hexo server   # 默认 http://localhost:4000

# 4. 确认没问题，提交并推送
git add .
git commit -m "新增：我的新文章"
git -c http.sslVerify=false push origin master

# 5. 等 1-3 分钟，GitHub Actions 自动部署
```

> **提醒**：改 `_config.yml` / `_config.stellar.yml` 后必须重启 `hexo server`，watch 只监听 `source/` 和主题模板，**不监听配置文件**。

## 十、踩坑汇总（建议收藏）

按"踩坑频率"从高到低：

| 坑 | 表现 | 解法 |
|---|---|---|
| **hexo server 不监听配置改动** | 改了 `_config.stellar.yml` 但页面没变 | 重启 `hexo server` |
| **Stellar canonical 大小写** | 顶部红色「非法克隆站」 | `originalHost` 必须小写 |
| **菜单不高亮** | 点分类页时"博客"按钮高亮 | 在 `source/<page>/index.md` 加 `menu_id` |
| **渐变背景不显示** | 配置写了但页面没渐变 | 加 `background-image: initial` 占位 + `!important` |
| **GitHub Actions 跳过 run** | 改了 workflow 后不自动部署 | 先推不带 workflow 改动的 commit |
| **github-pages 环境不允许 master** | 部署报错 environment protection rules | 在 Environments 设置里加 master 分支 |
| **favicon 还是旧图标** | 标签页图标没变 | 浏览器缓存严重，硬刷新或清缓存 |
| **浏览器显示旧 Jekyll Chirpy 内容** | 看到的是上一个博客的旧版 | 浏览器本地缓存问题，无痕窗口或清缓存验证 |
| **Git submodule 导致 CI 失败** | "did not contain <commit>" | 把主题从 submodule 转成普通目录 |
