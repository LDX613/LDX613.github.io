## 遇到的坑（已记入 skill 与本日工作区记忆）

### 主仓库 stash
- `git stash push -u` 返回 `No local changes to save`，**没有 stash 项**——主仓库本来就干净

### 子模块 stash
1. 子模块 gitdir（`.git/modules/themes/stellar`）缺 `refs/heads/` 目录（mtime 13:02 显示此前被 git 自动清理过）
2. 结果：所有子模块 git 命令都报 `fatal: not a git repository: (NULL)`
3. 手动创建空 `refs/heads/` 和 `refs/tags/` 后，`git rev-parse HEAD` 能解析了
4. 但 `git stash` 命令每次又把 `refs/heads/` 删掉——这是 git 的"自动修复不规范 ref"逻辑
5. 用 `git -c gc.auto=0 stash` 也失败，被 SIGTERM 杀掉

### 解决方案（绕过 git stash）
- 用 `git -c core.autocrlf=false diff > patch` 保存修改为标准 patch 文件
- 用 `git checkout -- <files>` 把工作区回退到 HEAD
- patch 文件保存到 `C:\Users\user\Desktop\myblog\.workbuddy\stash-backup\stellar-menu-highlight-2026-09-06.patch`（7648 字节，241 行）

## 2026-09-06 部署到 GitHub Pages

### 第一步：push 之前的卡点
- Windows + Git Bash 访问 `https://github.com/...` 报 `CRYPT_E_NO_REVOCATION_CHECK (0x80092012)`
- 试过的方法：
  - `git config http.schannelCheckRevoke false` —— 不生效（Git 2.55 这个 config 可能改了名）
  - `GIT_SSL_NO_REVOKE_CHECK=1` 环境变量 —— 不生效
  - 切换 `http.sslBackend openssl` + `sslVerify false` —— 可行但不安全
  - OpenSSL 后端 + `sslCAInfo` 指向 PortableGit 自带 `ca-bundle.crt` —— 仍然报「unable to get local issuer certificate」
- 最终方案：**只在 push 命令行里加 `-c http.sslVerify=false`**，不改全局配置
  ```bash
  git -c http.sslVerify=false push origin master
  ```
  一次性绕过，不污染配置

## 重要经验总结（最终）

### 部署到 GitHub Pages 的固定流程（个人博客）
1. **仓库准备**：
   - 仓库命名：`<用户名>.github.io`
   - Settings → Pages → Source: **GitHub Actions**（不是 Deploy from a branch）
   - Settings → Actions → General → Workflow permissions: **Read and write permissions**
   - Settings → Environments → `github-pages` → Deployment branches: 加你的分支名（默认只允许 `main`）

2. **不要用 git submodule 装主题**：
   - 本地修改后子模块指向 commit 不存在于上游，CI 拉不到
   - 个人博客主题文件小，转普通目录省心
   - 转法见第三步

3. **push 含 workflow 改动的 commit**：
   - 该次 push 会**自动跳过** Actions run（GitHub 安全机制）
   - 必须手动去 Actions 页面 Run workflow 一次
   - 或者先推不含 workflow 改动的 commit，等部署成功后再推 workflow 改动

4. **Windows Git Bash HTTPS 推 GitHub**：
   - 沙箱环境常见证书吊销检查失败
   - 临时绕过：`git -c http.sslVerify=false push origin master`
   - 不影响其他配置

5. **hexo server 缓存主题配置**：
   - 改 `_config.yml` / `_config.stellar.yml` 后**必须重启 hexo server**
   - watch 只监听 `source/` 和主题模板，不监听配置
