## 重要经验总结（最终）

### 部署到 GitHub Pages 的固定流程（个人博客）
1. **仓库准备**：
   - 仓库命名：`<用户名>.github.io`
   - Settings → Pages → Source: **GitHub Actions**（不是 Deploy from a branch）
   - Settings → Actions → General → Workflow permissions: **Read and write permissions**
   - Settings → Environments → `github-pages` → Deployment branches: 加你的分支名（默认只允许 `main`）

2. **不要用 git submodule 装主题**：
   - 本地修改后子模块指向 commit 不存在于上游，CI 拉不到
   - 个人博客主题文件小，转普通目录省心
   - 转法见第三步

3. **push 含 workflow 改动的 commit**：
   - 该次 push 会**自动跳过** Actions run（GitHub 安全机制）
   - 必须手动去 Actions 页面 Run workflow 一次
   - 或者先推不含 workflow 改动的 commit，等部署成功后再推 workflow 改动

4. **Windows Git Bash HTTPS 推 GitHub**：
   - 沙箱环境常见证书吊销检查失败
   - 临时绕过：`git -c http.sslVerify=false push origin master`
   - 不影响其他配置

5. **hexo server 缓存主题配置**：
   - 改 `_config.yml` / `_config.stellar.yml` 后**必须重启 hexo server**
   - watch 只监听 `source/` 和主题模板，不监听配置

## 2026-09-06 canonical 大小写修复（commit `bf1c527`）

- 用户反馈部署后访问 `https://ldx613.github.io` 看到红色「☠️ 本站为非法克隆站」提示
- 根因：Stellar 主题的客户端 JS 用 base64 比较 `canonical.originalHost` 与 `window.location.host`，base64 对大小写敏感
  - `_config.stellar.yml` 写的是 `originalHost: LDX613.github.io`（大写 L）
  - GitHub Pages 实际访问域名是 `ldx613.github.io`（小写 l，因为 GitHub Pages 自动小写用户名）
  - 大小写不一致 → 误判为克隆站
- 修复两处都改成小写：
  - `_config.yml`: `url: https://LDX613.github.io` → `https://ldx613.github.io`
  - `_config.stellar.yml`: `canonical.originalHost: LDX613.github.io` → `ldx613.github.io`
- 验证：hexo generate 后 `public/index.html` 里的 canonical link 已经是小写
- 注意：**Stellar 主题里硬编码了「非法克隆站」中文提示语**（不是 Chirpy 残留），user 一开始以为是被克隆站其实是 Stellar 自带的反盗用提示
- 主题 JS 里搜索关键字：`canonical|originalHost|isClone|克隆|location.host` 在 `themes/stellar/scripts` 和 `source/js` 里能定位判断逻辑

## 2026-09-06 用户问"为什么改成小写"

- 关键事实：GitHub Pages 永远把用户名规范化小写

## 关键经验（下次重启项目时参考）

1. **改主题配置后必须重启 hexo server** —— server 只 watch 模板和 source，不 watch `_config.stellar.yml`
2. **不要用 git submodule 装主题** —— 个人博客主题文件小，转普通目录最稳
3. **push 含 workflow 改动会被 Actions 跳过** —— 这次 push 不会自动部署，要手动触发或先推不含 workflow 的 commit
4. **GitHub Pages 用户名始终小写** —— url/canonical/originalHost 都用小写，避免 Stellar 反盗用机制误报
5. **hexo 文章 frontmatter 必须显式写 date** —— 否则用文件 mtime，git checkout 会改 mtime 导致时间乱
6. **Windows Git Bash HTTPS 推 GitHub** —— 沙箱证书吊销问题用 `git -c http.sslVerify=false push` 一次性绕过
7. **GitHub Pages 环境只允许指定分支部署** —— 默认 main，本项目是 master，要在 Settings → Environments 改
8. **浏览器缓存 GitHub Pages 同名 URL** —— 内容换了浏览器不知道，要无痕窗口或硬刷新验证
9. **Actions dashboard 状态可能滞后** —— 直接 `curl` 或 WebFetch 抓线上验证更可靠
10. **临时调试内容存 `.workbuddy/`** —— 不进 git，但 .workbuddy/ 整体在 .gitignore 里不会被误提交
