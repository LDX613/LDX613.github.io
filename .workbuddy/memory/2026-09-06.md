## 遇到的坑（已记入 skill 与本日工作区记忆）

### 主仓库 stash
- `git stash push -u` 返回 `No local changes to save`，**没有 stash 项**——主仓库本来就干净

### 子模块 stash
1. 子模块 gitdir（`.git/modules/themes/stellar`）缺 `refs/heads/` 目录（mtime 13:02 显示此前被 git 自动清理过）
2. 结果：所有子模块 git 命令都报 `fatal: not a git repository: (NULL)`
3. 手动创建空 `refs/heads/` 和 `refs/tags/` 后，`git rev-parse HEAD` 能解析了
4. 但 `git stash` 命令每次又把 `refs/heads/` 删掉——这是 git 的"自动修复不规范 ref"逻辑
5. 用 `git -c gc.auto=0 stash` 也失败，被 SIGTERM 杀掉

### 解决方案（绕过 git stash）
- 用 `git -c core.autocrlf=false diff > patch` 保存修改为标准 patch 文件
- 用 `git checkout -- <files>` 把工作区回退到 HEAD
- patch 文件保存到 `C:\Users\user\Desktop\myblog\.workbuddy\stash-backup\stellar-menu-highlight-2026-09-06.patch`（7648 字节，241 行）

## 重要：恢复方式
```bash
cd C:\Users\user\Desktop\myblog
mkdir -p .git/modules/themes/stellar/refs/heads .git/modules/themes/stellar/refs/tags  # 先补 refs/ 目录
git apply .workbuddy/stash-backup/stellar-menu-highlight-2026-09-06.patch
```

## 2026-09-06 用户反馈"没看见颜色变化"的排查
- 排查步骤：
  1. `curl http://localhost:4000/` —— 服务器返回的是 HTML（说明 hexo server 还在跑）
  2. 检查 `<div class="sitebg">` —— 5 处匹配，元素存在
  3. 对比磁盘 `public/index.html`（新渐变）与服务器响应（**旧紫色渐变**）
- 根因：**hexo server 启动后，主题配置 `_config.stellar.yml` 变更不会触发重新构建**。
  - hexo server watch 的是 `source/` 和主题模板文件，不包括用户配置
  - 旧进程一直用内存里的旧页面（紫色渐变），磁盘上生成的 `public/` 是新的
- 解决：
  - 杀 PID 28412（`taskkill /F /PID 28412`）
  - 用 `pnpm hexo server` 在后台启动新服务器（task_id=`w11uCH`）
  - `curl` 验证新服务器返回的就是 `#ECF7E1 → #D3E8B7 → #CDE7FA → #FFF4B6`
- 提醒用户：浏览器要按 Ctrl+Shift+R 硬刷新才能看到
- **重要**：以后改 `_config.yml` / `_config.stellar.yml` 后必须重启 hexo server，否则用户看不到效果
